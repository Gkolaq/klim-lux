# Klim & Co · Klim-Lux

Сайт мебельной мастерской Олега Климко в Варшаве: https://www.klim-lux.com. Единственный Sites-проект — `appgprj_6ac13fc8d10481918e5df6e700854015`. Сохранять public-доступ, D1 `DB`, R2 `BUCKET` и правки владельца.

## Сначала прочитать

Актуальные правила — в шапке [docs/project-context.md](docs/project-context.md), порядок проверки версии и выпуска — [docs/release.md](docs/release.md). Исторические номера в документах не определяют текущую публикацию.

Перед аудитом получить из native Sites опубликованную версию, успешный deployment и его source commit, открыть исходники штатным source workflow и выполнить:

```sh
npm run verify:source -- --project-id <точный-project-id> --published-commit <точный-commit-публикации>
```

Несовпадение HEAD, другой Site или несохранённые файлы останавливают аудит опубликованного кода. Не выдавать тесты старой папки за проверку рабочего сайта. Для новых правок явно указывать, что это ещё неопубликованный код.

## Языки и страницы

Действуют **PL, RU и EN** с префиксами `/pl/`, `/ru/`, `/en/`. Корень перенаправляется на PL. Старые BE/UK-адреса перенаправляются301 на соответствующий RU-адрес с сохранением параметров; это не отдельные действующие версии.

В каждом языке: главная, услуги и четыре страницы услуг, материалы, мастерская, контакты, каталог работ и отдельные работы, библиотека и авторские статьи. Каталог поддерживает серверный поиск, категории и постраничный вывод без JavaScript. Видимость работ определяет актуальный контент владельца; скрытое и удалённое намеренно не восстанавливать.

## Стек и команды

Astro, официальный адаптер Cloudflare, TypeScript, Zod, Drizzle и Wrangler. Точные версии — в `package.json` и `package-lock.json`; не дублировать устаревающий список. Node должен удовлетворять `engines.node`.

```sh
npm ci                       # только если зависимости отсутствуют или изменились
npm run check                # типы
npm run build                # Worker и подготовка Sites
npm test                     # изолированные тесты приложения, CMS, формы и SEO
npm run test:release          # регрессии контроля версии и выпускной проверки
npm run release:smoke -- --output /absolute/path/release-result.json
```

Для `release:smoke` нужны Python3 и curl. Он делает7–10 GET: главные и контакты PL/RU/EN, health и по одной работе, найденной в текущей главной каждого языка. Нет жёсткой зависимости от фото303. Если ссылки на видимую работу нет, пропуск явно записывается, удалённая работа не запрашивается. Письма и production-записи не выполняются.

Полный изолированный обход: `node scripts/audit-built.mjs /absolute/path/result.json` после сборки. Он проверяет актуальный sitemap, canonical, hreflang, H1, JSON-LD, локальные ресурсы и защиту служебных маршрутов. Это не проверка сенсорного телефона и не измерение Core Web Vitals.

## Хранение и форма

`db/schema.ts` и существующие `drizzle/*.sql` задают схему; runtime не создаёт таблицы. Исходное содержимое находится в `src/data/content.ts`. Пустые `site_content` и `automation_backup` означают предусмотренный source-default режим revision0. После сохранения контент читается из D1, revision защищает от перезаписи параллельных правок; R2 хранит загруженные файлы. JSON-копия содержит ссылки, а не байты всех фотографий.

Панель `/admin/` и операции изменения доступны только подтверждённому владельцу через существующий вход ChatGPT. Успешный вход посетителя не даёт ему права редактирования. Секреты и разрешённые аккаунты управляются штатными Sites-настройками; не переносить ключи в код или отчёты.

Контактная форма на основном домене использует серверный `/api/contact/`. Доставка согласованного письма подтверждена14.10.2026; новый реальный тест для изменений документации/проверок не нужен. Аналитика фиксирует `generate_lead` только после принятия сервером и при согласии посетителя, без содержимого сообщения.
