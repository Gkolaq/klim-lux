# Klim-Lux: источник, проверка, выпуск и продолжение

Редакция16.10.2026. Выполнять цельный согласованный этап, подходящие проверки и сохранение результата. Успешные проверки с неизменившимися входами не повторять. Отдельные старые задания отключены; единственный объединённый мониторинг разрешён владельцем и остаётся активным.

## Обязательная проверка источника

1. В native Sites подтвердить точный `project_id`, public-доступ, **текущую успешную публикацию** и её source commit. Последняя сохранённая версия может быть неопубликованной. Статический номер в памяти, README или `.openai/release-baseline.json` не заменяет native результат.
2. Открыть исходники штатным Sites source workflow. Credentials передавать только через скрытый stdin; не сохранять в файлах/аргументах. Не сбрасывать чужие незавершённые правки.
3. До тестов опубликованного кода выполнить `npm run verify:source -- --project-id <точный-native-id> --published-commit <точный-native-commit>`. При несовпадении, грязном дереве или другом проекте остановиться, сохранить находку и восстановить правильный источник. Не подписывать тесты v34 как результат v36.
4. Записать время, version_id, source commit, deployment_id/status и результат сравнения в контрольную точку. Для новых неопубликованных изменений вести отдельный результат; не подменять им базовую проверку публикации.

## Подходящие проверки

| Изменение | Проверка |
| --- | --- |
| Меню, просмотр фото, клиентская форма | `npm run test:ui` |
| Серверная почта | `node --test tests/contact-mail.test.mjs` |
| Аналитика | `node --test tests/analytics.test.mjs` |
| CMS, загрузки, права, данные | `node --test tests/cms.test.mjs` и затронутые тесты |
| Контроль версии и выпуска | `npm run test:release` |
| Полный аудит по запросу или подтверждённая общая регрессия | `npm run check`, `npm run build`, `npm test`, `npm run test:release`, `node scripts/audit-built.mjs /absolute/path/report.json`, `npm audit --omit=dev --json` |

Если изменены TypeScript/компоненты — один `npm run check`. Для полного набора сохранить результат каждой команды и источник. Все публичные маршруты проверять по текущему sitemap, отдельно показывать RU/PL/EN; BE/UK проверять как301 наRU. Существующие тесты используют изолированные D1/R2 и подменяют внешнюю почту/IndexNow; реальные заявки и production-изменения для них не нужны.

Для документации и Python-инструментов проверять затронутые инструменты; неизменённые runtime, сборку и полный обход повторять не требуется. Зависимости устанавливать только при необходимости. Не менять lockfile, версии или схему без причины.

## Публикация

1. Сохранить проверенный предшественник как точку отката. `.openai/release-baseline.json` — датированная точка, а не автоматически обновляемый указатель рабочего сайта.
2. Source helper отправляет точный commit и возвращает архив этого исходного состояния. Выполненные проверки/сборку с неизменившимися входами не повторять. Сохранить версию с возвращёнными `project_id`, `commit_sha`, `archive` и опубликовать возвращённый `version_id` в тот же Site. Сохранить public, DB/BUCKET и runtime-настройки.
3. Для pending/building/publishing ждать ту же операцию; succeeded завершает опрос, failed не считать готовым выпуском.
4. Один `npm run release:smoke -- --output /absolute/path/release-result.json`:7 обязательных GET (главные и контакты PL/RU/EN, health), затем до3 GET работ по ссылкам из этих же опубликованных главных. Всего7–10 запросов, до3 параллельно, без полного внешнего обхода. HTTP/язык/canonical/H1/noindex, меню, server-форма/поля, просмотр фото и D1/R2; без писем. Отсутствующая ссылка на работу явно отмечается как пропуск, удалённая работа не подставляется.
5. Сохранить точные номер/commit/status и результаты; различать полный локальный аудит и ограниченную живую выборку. Smoke не доказывает browser/touch QA или принадлежность исходников: источник подтверждается отдельно шагами выше.

## Контрольная точка и продолжение

После каждого основного этапа обновлять один отчёт и архив: цель, native версия/commit, завершённые проверки и логи, находки, сделанные изменения, оставшееся, точная следующая команда. Обновлять существующие файлы с проверкой их текущей версии. Код сохранять в Git/Sites; не архивировать секреты, node_modules и копию Git в отчёте.

После обрыва сначала читать короткий текущий блок и `resume.json`. Сверить native источник, а не доверять оставшейся локальной папке. Продолжать незавершённый этап. Старые Google/GA4-действия, письма и полные тесты не повторять лишь из-за нового сообщения «продолжай». Единственный мониторинг имеет отдельную read-only политику и лимиты; ручной полный аудит их не расширяет.

## Откат и границы проверки

Реальный откат выполнять при подтверждённой регрессии кода на проверенный `version_id` того же Site. Не откатывать контент владельца, R2, DNS и секреты. Версия исходников не является резервной копией данных; изменения схемы требуют отдельной проверки совместимости.

Изолированная проверка при необходимости: `node scripts/verify-rollback.mjs /absolute/current-source /absolute/previous-source` для двух уже собранных каталогов. Проверка31→30→31 от14.10 подтверждала сохранность тестовых D1/R2; это историческое доказательство, не повод повторять production-откат.

Физическая QA телефона остаётся отдельной задачей при конкретном сбое или видео владельца. Core Web Vitals без измерения не заявлять. Дизайн, тексты и фото сохранять; не восстанавливать намеренно скрытое и не дробить продвижение на нескончаемые мелкие PL-title правки.
