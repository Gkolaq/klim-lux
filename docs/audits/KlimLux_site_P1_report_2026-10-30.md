# KLIM-LUX — P1, действующий сайт: заявки, контакты, SEO

Проверка 30.10.2026. Область: только `https://www.klim-lux.com/`, без изменений production.

## Результаты P1

- Браузерный проход польской версии: главная навигация, услуги, портфолио, библиотека и контакты доступны. На странице контактов видны поля имя/контакт/сообщение, кнопка отправки и телефон/email; JS-обработчик формы обнаружен. На проверенных страницах нет признаков отсутствующих изображений. Мобильный режим 390px не проверен.
- Независимый извлекатель HTML проверил формы `/pl/contacts/`, `/ru/contacts/`, `/en/contacts/` и фактический атрибут `data-delivery="server"` на всех трёх. Это подтверждение серверного режима UI, **не** доказательство принятия/доставки конкретной новой заявки.
- Resend: домен отправителя `mail.klim-lux.com` verified; отправка включена. Есть две исторические операции со статусом delivered (14.10 и 25.10.2026) по теме обращения с сайта. Источник этих отправок и нынешняя доставка через web form не проверялись. Зафиксирован один `POST /emails` с HTTP 422 от 28.10, принадлежность текущему каналу не установлена; не объявлять дефектом production без причинной связи.
- Доступ `/admin/` для анонимного запроса ранее возвращал 401; ссылка на него в подвале публична, но сама по себе не доказывает уязвимость. Вопрос скрытия ссылки — отдельно от действительности авторизации.
- Загрузка файлов через публичную форму отсутствует, сайт направляет фото на email. Не добавлять файлообмен без отдельного безопасного проекта (антивирус, размер, хранение, права доступа и приватность).

## Выполненное инженерное улучшение

В существующей отдельной ветке GitHub `maintenance/live-smoke-20261030` расширен read-only smoke-checker: добавлены проверки GET `/pl|ru|en/contacts/`, HTTP 200, наличия формы `#contact-form`, серверного `data-delivery`, полей `name/contact/message`. Клиентские данные не отправляются.

Проверки на изолированной локальной фикстуре: `node --test klim-live-smoke.test.mjs`: **4/4 PASS**. Негативные случаи: неверный canonical, переключение формы в draft и исчезновение поля. Это **не** полноценное тестирование реального POST или JavaScript в production.

## Ограничения и следующий приоритет

Действующий исходник Sites v50 и его source SHA не доступны инструментам текущего чата, поэтому правки приложения в production не публиковались и старая копия GitHub не использовалась для обновления Sites. Для настоящего end-to-end подтверждения нужна контролируемая тестовая заявка с проверкой принятия backend и доставки; не использовать клиентские данные и не слать запрос без отдельного сценария. Следующая инженерная задача — открыть текущий Sites source через штатную среду Work и перенести проверенный P1-автотест без перезаписи кода.

**Зафиксированная граница проекта:** в этом этапе обслуживается только основной Sites. Все альтернативные площадки, зеркала и миграции исключены из задач и мониторинга.
