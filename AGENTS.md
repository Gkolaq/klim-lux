# Klim-Lux: инструкции для Codex

Работать из корня этого репозитория. Сначала прочитать этот файл, короткую текущую шапку `docs/project-context.md`, `docs/work-state.json` и `docs/release.md`. Текст под заголовками «История»/Historical — архив, а не текущие указания. Отвечать владельцу по-русски, кратко и по фактам.

## Источник и границы

- Сохранять единственный Site из `.openai/hosting.json`, public-доступ, D1 `DB`, R2 `BUCKET`, секреты и правки владельца. Не создавать второй проект.
- Перед аудитом публикации получить из native Sites её успешный deployment и точный source commit, открыть исходники штатным source workflow и выполнить `npm run verify:source -- --project-id <native-id> --published-commit <native-commit>`. Другой HEAD, проект или грязное дерево останавливают аудит опубликованного кода. Не выдавать старую локальную папку за текущий сайт.
- Если native Sites недоступен, можно работать с имеющимися исходниками, но результат обозначать как локальный/неопубликованный. Не выдумывать публикацию, подключение или состояние другой сессии Codex. Не сбрасывать и не перезаписывать несохранённую работу.
- Действуют PL/RU/EN. Старые BE/UK должны давать301 на соответствующий RU-адрес с сохранением параметров. Проверять все действующие языки. Дизайн, тексты, фото, намеренно скрытые работы и коммерческие факты сохранять.

## Проверки без лишнего расхода

- Точные команды и версии брать из `package.json`/lockfile. `npm ci` нужен только при отсутствии зависимостей или изменении их входов. Не устанавливать Codex CLI, браузеры, платные сервисы или новые зависимости для обычного аудита.
- TypeScript/компоненты: `npm run check`; приложение/CMS/форма: `npm test` после необходимой сборки; выпускные инструменты: `npm run test:release`. Менять и тестировать подтверждённую причину. Успешные команды с неизменившимися входами не повторять после каждого «продолжай».
- Полный обход `scripts/audit-built.mjs` — при прямом запросе или общей регрессии, а не для служебной документации. Полный успешный аудит16.10 уже сохранён. Локальный обход не называть полным внешним обходом, браузерной QA или Core Web Vitals.
- Тесты используют изолированные D1/R2 и подменяют внешнюю почту/IndexNow. Не отправлять реальные письма, не создавать заявки и не изменять production-данные ради теста. Не повторять неизменённые запросы индексацииGoogle.
- После необходимой публикации выполнить `release:smoke` один раз: он проверяет все3языка и выбирает актуальные работы из опубликованных главных. Не подставлять жёсткий ID фото. Подходящие успешные сборки/тесты не повторять при упаковке с прежними входами.

## Сохранение и зависания

- После каждого существенного этапа сохранять цель, точный источник, результат/лог, изменения, оставшееся и следующую команду. Код — в Git/Sites; журнал и архив — в существующих файлах KlimLux_project_audit_2026-10-15.md / KlimLux_audit_2026-10-15.zip с проверкой текущей версии. При доступной Library брать свежий текущий блок KlimLux_status_2026-10-03.md; при её отсутствии использовать `docs/work-state.json` как датированную передачу, а не указатель live-версии.
- При возобновлении сначала читать точку продолжения. Не начинать законченный цикл заново. Не запускать вторую задачу, которая одновременно меняет тот же checkout; не останавливать неизвестные процессы вслепую.
- Если Codex/команда зависли, сначала установить, что именно ждёт: подтверждение, вход, терминал, сеть или тест. Использовать ограниченное время выполнения и сохранять последний вывод. Timeout/недоступная сессия — неизвестный результат, не доказанная ошибка сайта и не успешный тест.
- Единственный объединённый мониторинг работает отдельно по read-only политике; новых расписаний не создавать. Ключи, cookies, токены, пароли и необработанные production-payload не сохранять в исходниках, журналах и отчётах.
